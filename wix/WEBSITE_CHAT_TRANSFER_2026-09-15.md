## 9. SEO ROUTE-OWNERSHIP REPAIR — PUBLISHED, FINAL PUBLIC VERIFY UNDERWAY

### Defect proven before repair

The initial server HTML for canonical SPA routes inherited Home SEO (`Home | Behavioral Bridge` + Home description) even when React later changed `document.title`. `/_wix/pages.json` was swallowed by the old catch-all route and returned HTML rather than a registry JSON document.

Root cause was `src/pages/[...slug].astro` resolving every URL with `itemData.pageName: 'Home'`.

### Official Wix docs used as source of truth

Main pages:
`https://dev.wix.com/docs/go-headless/wix-managed-headless/full-integration-astro/feature-guides/seo/manage-seo-for-main-pages`

Blog/item pages:
`https://dev.wix.com/docs/go-headless/wix-managed-headless/full-integration-astro/feature-guides/seo/add-seo-support-to-item-pages`

The docs establish:
- fixed main pages should exist as actual Astro routes and receive Wix-managed SEO through the page registry
- shared layout should not compete with Wix-managed title/description/canonical/social tags
- registry lives at `/_wix/pages.json`
- Blog item routes need `wixMetadata`
- Blog uses `WIX_APPS.blogs.postPageMetadata`, `slug`, `seoTags.ItemType.BLOG_POST`
- item SEO should use `x-wix-forwarded-url` first and `Astro.url.href` only as fallback.
